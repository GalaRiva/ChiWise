# Chi Wise Magic — Flutter

Исходники приложения Chi Wise Magic — психологический инструмент на основе
CBT-практики «Квадрат Декарта», обёрнутый в геймификацию (16 локаций
мистического/космического путешествия) и тактильный «Магический Шар».
Полная архитектура, модели данных и все решения по неоднозначностям ТЗ — в
`../FLUTTER_ARCHITECTURE_PLAN.md` (корень проекта, на уровень выше этой папки).

Все 12 этапов разработки (см. план ниже) реализованы и вручную проверены.

## Важно: как получен этот код

Разработка велась в среде без установленного Flutter SDK и без доступа к
`storage.googleapis.com`/pub.dev, поэтому `flutter create`, `flutter pub get`,
сборка и запуск на эмуляторе здесь ни разу не выполнялись. Весь код — от
скелета проекта до самого сложного экрана — написан вручную, без компилятора
и без `flutter analyze`. Это значит:

- Синтаксис Dart выверен внимательно, но НЕ гарантирован безошибочным —
  первая же реальная сборка на вашей машине может вскрыть 1-2 опечатки или
  устаревшие сигнатуры сторонних пакетов.
- Места, где сигнатура стороннего API (RevenueCat, `in_app_review`,
  `url_launcher`, `fl_chart`, `firebase_analytics`) не была стопроцентно
  очевидна без документации под рукой, помечены комментариями
  `// TODO(пакет X.Y.Z): сверить сигнатуру` прямо в коде — это ПОЛНЫЙ список
  мест, требующих внимания при первой сборке, ищите по `TODO(` в `lib/`.
- Реальных ассетов (иконки локаций `.webp`, Lottie-анимации редких небесных
  явлений `.json`, шрифты через `google_fonts` — они подтягиваются в рантайме)
  в проекте нет — только пути-заготовки в коде. Отсутствие Lottie-файлов не
  ломает приложение (см. `RareEventOverlay`, `errorBuilder` тихо скрывает
  виджет), но карта локаций будет визуально пустой без реальных `.webp`.

## Что нужно сделать на вашей машине, чтобы проект ожил

```bash
cd chiwise_flutter
flutter pub get
flutter gen-l10n                           # сгенерирует AppLocalizations из lib/core/localization/l10n/*.arb
flutter create . --platforms=android,ios   # доставит недостающие android/ и ios/ обвязки
flutterfire configure                      # свяжет проект с Firebase, создаст lib/config/firebase_options.dart
flutter run
```

После этого раскомментируйте блоки, помеченные `// TODO` в `lib/main.dart`:
инициализацию Firebase (`Firebase.initializeApp`), Crashlytics
(`setCrashlyticsCollectionEnabled`) и RevenueCat (`PurchasesService().configure`,
нужен API-ключ из дэшборда RevenueCat). До этого момента приложение полностью
рабочее — все эти интеграции защищены try/catch и молча деградируют без
конфигурации (см. «Архитектурные защитные паттерны» ниже), это ОЖИДАЕМОЕ
поведение, а не баг.

## Что реализовано — по этапам

0. **Скелет проекта** — `pubspec.yaml`, тема (Deep Blue/Emerald/Turquoise/Soft
   Gold, Montserrat/Inter), `go_router`, локализация 5 языков, все data-модели.
1. **Онбординг + Авторизация** — 4 свайп-экрана, Google/Apple/анонимный вход,
   account linking без потери данных анонимного пользователя.
2. **Движок решений** — 5 экранов Квадрата Декарта, автосохранение черновика в
   Hive, авторасширяющиеся поля, учёт объёма текста и backspace для будущих
   ачивок.
3. **«Принятие решения» + CRUD** — сохранение с `status: completed`,
   Hive-first + best-effort Firestore-зеркало, просмотр/редактирование записи.
4. **Карта локаций** — 16 локаций с формулой порогов `5 + 2×(level-1)`,
   матовое стекло на заблокированных, профиль пользователя.
5. **Магический Шар** — `sensors_plus` (тряска), встроенный `HapticFeedback`,
   энергия/лимит вопросов, детект удержания слабой тряски ≥15с.
6. **Монетизация** — RevenueCat-обёртка (`PurchasesService`), Paywall
   (месяц/год/lifetime), восстановление покупок.
7. **Оценка приложения** — кастомный UI 5 звёзд после 3-го и 10-го решения,
   1-3★ → email поддержки, 4-5★ → `in_app_review`.
8. **Система достижений** — 14 ачивок (10 обычных + 4 секретных под матовым
   стеклом с загадкой), движок условий (`AchievementEvaluator`), 3D-флип
   карточки на цитату (упрощённый, через `AnimatedSwitcher`).
9. **Шкала осознанности** — 5 уровней, начисление очков за решения/ачивки,
   неоморфная капсула прогресса с fluid-анимацией.
10. **WOW-эффекты** — «дыхание интерфейса» (кастомный `CustomPainter`,
    реагирует на скорость набора текста), bubble chart истории решений
    (`fl_chart`, размер = объём текста, цвет = категория), Lottie редких
    небесных явлений (затмение/парад планет) при streak ≥ 3.
11. **Полная локализация** — все 5 arb-файлов синхронизированы (138 ключей
    каждый, проверено скриптом), форматирование цены Paywall под локаль
    (`intl.NumberFormat.currency`), экран настроек с переключателем языка
    (персистентный) и статусом подписки.
12. **Аналитика + Crashlytics** — `AnalyticsService`/`CrashlyticsService`,
    события на ключевых точках (решение завершено, ачивка получена, вопрос
    Шару, покупка подписки, оценка приложения, левел-ап), глобальный перехват
    необработанных ошибок в `main.dart`.

## Архитектурные защитные паттерны (важно понимать перед доработкой)

Firebase, RevenueCat и другие внешние SDK не сконфигурированы в среде
разработки — по всему проекту соблюдён единый принцип: **конструктор/провайдер
сервиса никогда не обращается к SDK напрямую; каждый публичный метод сам
оборачивает вызов в `try/catch` и молча деградирует** (возвращает `null`/пустой
результат/ничего не делает), а не бросает исключение наружу. Это позволяет
остальному приложению (роутер, экраны, redirect-логика) работать нормально,
даже когда Firebase/RevenueCat не инициализированы. См. эталонные примеры:
`lib/services/purchases_service.dart`, `lib/services/review_service.dart`,
`lib/services/analytics_service.dart`, `lib/services/crashlytics_service.dart`.

Второй сквозной паттерн — sentinel-флаги в `copyWith()` там, где нужно явно
сбросить nullable-поле в `null` (обычный `value ?? this.value` для этого не
годится): см. `UserModel.copyWith(clearSubscriptionExpiresAt: ...)`,
`MagicBallState.copyWith(clearAnswerText: ..., clearBlockReason: ...)`.

## Известные ограничения / зоны роста

- `DecisionModel.tag` (категория решения) выбирается на экране «Принятие
  решения» с Этапа 10 — ачивки `planet_parade`/`perfect_alignment` рассчитаны
  на эти теги и заработают на реальных данных пользователей, но UI появился
  поздно в разработке, ретроактивных тегов у старых решений не будет.
- Настоящих `.webp`/`.json`-ассетов (иконки локаций, Lottie-анимации) в
  проекте нет — только пути-заготовки. Нужно подключить дизайнеру перед
  релизом (`assets/images/locations/`, `assets/lottie/`, см. `pubspec.yaml`).
- В `lib/presentation/screens/` и `lib/presentation/widgets/` остались
  1-2 пустые директории-заготовки (`.gitkeep`) от исходного скелета Этапа 0,
  чьи фичи в итоге реализованы под другими именами (`mindfulness/` вместо
  `profile_stats/`, `rating/` вместо `rating_flow/`) — безвредны, можно удалить.

## Чеклист перед релизом

1. `flutter pub get && flutter gen-l10n && flutter analyze` — прогнать
   статический анализ и исправить всё, что всплывёт (ожидаемо немного, см.
   «Важно: как получен этот код» выше).
2. Пройтись по всем `// TODO(` в `lib/` — сверить сигнатуры сторонних пакетов
   с их реальной документацией на момент сборки.
3. `flutterfire configure` — подключить реальный Firebase-проект (Auth,
   Firestore, Analytics, Crashlytics), раскомментировать инициализацию в
   `lib/main.dart`.
4. Завести продукты в RevenueCat/App Store Connect/Google Play Console
   (`sub_monthly_6`, `sub_yearly_24`, `lifetime_access` — см.
   `lib/presentation/providers/paywall_provider.dart`), получить API-ключи,
   передать в `PurchasesService().configure(apiKey)`.
5. Подключить реальные ассеты: иконки 16 локаций, Lottie-анимации редких
   явлений, иконку приложения и splash screen (пакеты `flutter_launcher_icons`/
   `flutter_native_splash` в проект пока не добавлены).
6. Проверить Firestore Security Rules (`firestore.rules` в корне
   `chiwise_flutter/`) под реальные требования безопасности перед продакшеном.
7. Настроить `bundle id`/`applicationId`: `com.chiwisemagic.app` (см. ТЗ) —
   после `flutter create . --platforms=android,ios` нужно вручную выставить
   этот идентификатор в `android/app/build.gradle` и Xcode-проекте.
8. Заполнить страницы в App Store Connect/Google Play Console (описание,
   скриншоты, политика конфиденциальности — email поддержки
   `egorova.esp@gmail.com` уже зашит в код rating flow).
9. `flutter build appbundle` (Android) / `flutter build ipa` (iOS).

## Локализация

5 языков — `ru`/`en`/`es`/`fr`/`pt` (файлы в
`lib/core/localization/l10n/*.arb`), 138 ключей, все синхронизированы.
Переключатель языка — экран «Настройки» (`SettingsScreen`), выбор
персистентен через `SharedPreferences`; по умолчанию — язык устройства.
